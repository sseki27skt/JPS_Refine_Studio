# 実装計画: 新規プロジェクト立ち上げを起点とするアプリローンチ構造への刷新

## 1. 概要と背景
現在、システムは起動時に `gagaku_default`（雅楽コレクション）が自動生成・デフォルト選択されており、研究プロジェクト一覧に最初から雅楽が入っている状態です。
しかし、本システムは雅楽に限らず文学、美術、歴史、地理など幅広い人文学・文化資源の研究対象を扱うユーザーを想定しています。
そのため、最初から特定のコレクションを固定せず、**「新規プロジェクト立ち上げ」からアプリ全体をローンチ（開始）できるUX**へ刷新します。

---

## 2. 変更・改善方針

### A. ワークスペースマネージャーの汎用化 (`01_cleansing_studio/modules/workspace_manager.py`)
1. **雅楽デフォルトプロジェクトの強制自動生成を廃止**:
   - `DEFAULT_WORKSPACE_ID = "gagaku_default"` の強制生成ロジックを排除。
   - `_migrate_legacy_data_if_needed()` において、無条件に `gagaku_default` ワークスペースを作成・初期化するのを停止。
   - 既存の空の `gagaku_default` フォルダをプロジェクト一覧から除外（またはクリーンアップ）。
2. **プロジェクト削除の自由化**:
   - 「デフォルトワークスペースは削除できません」という制限を撤廃し、ユーザーが不要なプロジェクトを自由に削除可能にする。
3. **ワークスペースメタ情報の拡張**:
   - `research_theme`（研究テーマ・関心領域）をメタデータとして保存できるようにし、Step 1（データ取得）との親和性を向上。

### B. アプリのローンチ制御・ルーティング改善 (`01_cleansing_studio/app.py`)
1. **未作成・未選択時のローンチ体験（Welcome & Project Launcher）**:
   - プロジェクトが0件、または未選択の場合、サイドバーの工程選択を無効化（または注意喚起）し、メイン画面に**洗練された新規プロジェクト立ち上げ画面（プロジェクト作成フォーム）**を表示。
   - 「JS-Refine Studio」が人文学文化資源全般に対応する汎用システムであることを明示。
2. **サイドバーUIの改善**:
   - プロジェクトが0件の場合は「📁 プロジェクト未作成」と表示し、ワンクリックで作成画面へ誘導。
   - プロジェクトが存在する場合は選択セレクタに加え、「➕ 新規プロジェクト作成」ボタン・導線を常設。
3. **プロジェクト作成後の自動遷移**:
   - 新規プロジェクト作成完了後、即座にそのプロジェクトをアクティブ化し、Step 1（またはダッシュボード）へスムーズに遷移。

### C. プロジェクト管理ビューの刷新 (`01_cleansing_studio/views/workspace_view.py`)
1. **新規作成起点のUI構成**:
   - プロジェクトが未作成の場合はウェルカムカードと新規プロジェクト作成フォームを前面に配置。
   - 既存プロジェクトがある場合も、一覧と新規作成を分かりやすく整理。
2. **研究テーマの入力欄追加**:
   - プロジェクト名・IDだけでなく、「研究対象・関心テーマ（例: 江戸の出版文化、近代絵葉書資料、仏教美術など）」を入力可能にし、初期設定として保存。

### D. 各ステップにおける雅楽ハードコードの汎用化
1. **Step 1 (`01_cleansing_studio/views/step1_fetch_view.py`)**:
   - テーマ入力の固定初期値 `"日本の古典籍における楽譜資料"` を廃止。
   - アクティブなワークスペースで設定された研究テーマ（または名称）を初期値として反映。未設定の場合はプレースホルダーで柔軟に入力可能にする。
2. **Step 5 (`01_cleansing_studio/views/step3_export_view.py`)**:
   - Mermaidフロー図の `真正楽譜資料メタデータ` 表記を `確定・採択対象資料メタデータ` に汎用化。
   - 雅楽・音楽に特化したジャンル推論フォールバックを、より汎用的な分類（またはプロジェクト設定に応じた処理）に調整。

## 3. 変更対象ファイル一覧
1. `01_cleansing_studio/modules/workspace_manager.py` (コアロジック)
2. `01_cleansing_studio/app.py` (メインエントリー・ルーティング)
3. `01_cleansing_studio/views/workspace_view.py` (プロジェクト作成・管理画面)
4. `01_cleansing_studio/views/step1_fetch_view.py` (テーマ初期値の動的化)
5. `01_cleansing_studio/views/step3_export_view.py` (表記の汎用化)
6. `data/workspaces/gagaku_default` (空ディレクトリのクリーンアップ)

---

## 4. 検証計画
- ワークスペースが0件の状態でアプリを起動し、新規プロジェクト立ち上げ画面が正しく表示されること。
- 新規プロジェクト（例: `ukiyoe_archive`, `近代文学資料` 等）を作成し、即座にアクティブ化されてStep 1に反映されること。
- プロジェクト切り替え、削除が正常に行えること。
- 自動テストおよびUI動作の確認。
